# ADR-0001 — Fast DDS как стартовое транспортное ядро

**Дата:** 2026-11-05  
**Статус:** Accepted as project direction; implementation pending

## Контекст

Задача D2S — дать понятные SDK и, в перспективе, федерацию поверх проверенного DDS. Полная собственная реализация DDSI-RTPS увеличивает сложность, риск несовместимости и объём тестирования.

## Решение

Начать с eProsima Fast DDS на C++; использовать его стандартные DomainParticipant, Topics, writers/readers, Discovery и QoS. Для языков рассмотреть bindings через управляемый слой и стабильную D2S ABI, но не объявлять ABI утверждённой до прототипа.

## Последствия

Плюсы: готовая реализация протокола и типов; совместимость с upstream-инструментами при правильной настройке. Минусы: ограничения upstream QoS, платформ, ABI и discovery; зависимость от корректности версии Fast DDS.

## Альтернативы

Cyclone DDS, RTI Connext и реализация транспорта с нуля. Отложены без отрицательной оценки; возможна будущая модель сменных DDS backend adapters.

## Проверка

Собрать минимальный C++→Python типизированный обмен и измерить накладные расходы оболочки относительно чистого Fast DDS.
