# ADR-0003 — DomainId, logical domain и identity разделены

**Дата:** 2026-11-05  
**Статус:** Accepted separation; representation undecided

## Контекст

Рассматривался UUIDv7 в качестве основного идентификатора DDS-домена и вложенный адрес `Global:A:B`. В Fast DDS DomainId — числовой параметр DDS для обнаружения/связи, а не глобальное имя сети. UUIDv7 не помещается в DomainId без потери уникальности.

## Решение

- Для local MVP пользоваться стандартным DDS `DomainId`.
- Не требовать `network_id: UUID` для первоначального подключения.
- Будущий `logical_domain_id` должен быть независим от числового DDS DomainId.
- Не связывать идентичность участника с его текущим сетевым локатором.
- Не утверждать формат `logical_domain_id` до исследования federation trust model.

## Последствия

Простой local SDK сегодня и возможность вводить независимое глобальное пространство имён позже. Появляется задача отображения logical domain → физические DDS-домены и проверки коллизий/политик на мостах.

## Альтернативы

UUIDv7/v4, подписанные public-key identities, глобальный реестр, вложенные числовые домены. Ни один из этих вариантов не принят как обязательный механизм федерации.
