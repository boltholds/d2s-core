# ADR-0004 — Rust-first Core поверх Fast DDS через CXX

**Дата:** 2026-11-05  
**Статус:** Accepted for Phase 0; requires build/test validation

## Контекст

Для локального MVP сначала рассматривался собственный C++20 Core с SDK на Python. Решено начать с Rust, вызывающего C++ API eProsima Fast DDS, чтобы базовая логика и будущая федерация развивались на одном языке.

## Решение

- Высокоуровневый Core и публичный прототип API — Rust edition 2024.
- Нативный DDS backend — eProsima Fast DDS 3.x, C++20.
- Граница Rust/C++ — CXX; все Fast DDS типы и указатели скрыты в нативном адаптере.
- Один IDL-тип и два самостоятельных Rust-процесса (publisher/subscriber) для Phase 0.
- Tokio используется для ожидания matching и периодического опроса DataReader.
- Отдельная стабильная C ABI и SDK других языков — после проверки Core и требований ABI.

## Почему

Сокращает объём собственного C++, позволяет развивать routing/federation в Rust, сохраняет доступ к совместимой DDS/RTPS реализации, без написания собственной сетевой сериализации.

## Последствия

Плюсы: явные границы ответственности, безопасный Rust API, меньше внешнего unsafe-кода. Минусы: дополнительная сборка Fast DDS-Gen/C++, вопросы нативного ABI, сложность callbacks и потокобезопасности.

## Статус тестирования

В репозитории добавлены исходники и CI для сборки/двухпроцессного теста. Пока CI не завершилась успешно, считать прототип *непроверенным*.

## Проверка

Успешный `cargo build`, повторяемый smoke-test со всеми тремя сообщениями, проверка graceful teardown, затем профилирование. Только после этого начинать делать обобщённый SDK.
