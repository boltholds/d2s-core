# Модель безопасности и угрозы

**Статус:** Proposal. Безопасность должна сопровождать MVP и глобальные расширения.

## Что нужно защищать

- Содержимое пользовательских данных.
- Метаданные: Topics, типы, участники, соседства и адреса.
- Аутентичность писателей, читателей, мостов и управляющих сообщений.
- Целостность политик, маршрутов, схем и административных операций.
- Доступность при недоверенных подписчиках и сетевых атаках.

## Локальный DDS

Использовать DDS Security в поддерживаемой Fast DDS конфигурации: identity authentication, permissions, cryptographic protection. Граница доверия — только там, где реально активированы плагины, ключи и соответствующая политика. Номер DomainId, названия Topics и Partition QoS **не секреты** и не заменяют ACL.

## Федерация: принцип default deny

Права публикации, подписки и транзита должны быть самостоятельными проверками. Маршрутное соседство не создаёт авторизации. Каждый мост повторно проверяет политику, а получатель проверяет origin, чтобы нельзя было обойти запрет через доверенного соседа.

**Не утверждено:** централизованный CA, Web-of-Trust, делегированные trust roots, двустороннее согласие доменов на связь и механизм безопасного отзыва. Все варианты сравнить до глобальной реализации.

## Web Gateway

Требуется самостоятельная модель authentication/authorization, rate limits, tenant separation, защита от небезопасного динамического выбора Topics и schema-bombs. Gateway не должен раскрывать DDS-сеть целиком из браузера. Токены пользователя — не эквивалент DDS peer identity.

## Угрозы, которые необходимо тестировать

| Угроза | Минимальное требование |
|---|---|
| Поддельный peer | Проверка identity до принятия маршрутов |
| Подмена маршрутного объявления | Подлинность, freshness, TTL/expiry |
| Маршрутная петля | Hop limit, request ID, bounded dedup |
| Неправомерный транзит | Проверка policy для каждого действия |
| Утечка topology | Scoped discovery, минимум метаданных |
| Replay старого control message | Nonce/sequence/expiry |
| QoS и buffer exhaustion | Backpressure, quotas, resource limits |
| Компрометация relay | Отсутствие неявного доверия к payload/origin |
| Отказ ключа/права | Закрытие запрещённых направлений, аудит |

## Непереговорные инварианты

- Deny остаётся deny при альтернативном маршруте.
- Потеря связи с control plane не превращается в «разрешить всё».
- При отсутствии подтверждённой идентичности междоменная передача не запускается.
- Debug/monitoring не раскрывает полезную нагрузку посторонним участникам.
- Логи не содержат секретов и необработанных ключей.

Security review и fault-injection обязательны прежде чем назвать federation production-ready.
